# F8.5 · Proyectos — Plan de implementación

> **Para agentes:** ejecución nativa (`.claude/rules/workflow.md`): Claude implementa cada tarea en esta sesión, en bloques, con dos revisiones intermedias y una final acotada. Pasos con casillas (`- [ ]`).

**Objetivo:** abrir un repo con `.smalti/layout.json` desde ⌘K o ⌘O con su layout y sus comandos, tras una confirmación que muestra lo que cambió, sin coste en reposo; publicado como 0.8.5.

**Arquitectura:** el dominio (`SmaltiCore`) valida el archivo como layout de proyecto, descubre la raíz hacia arriba, decide si abrir, confirmar o saltar y mantiene los recientes y la aprobación; dos puertos (`ProjectFiles`, `ProjectRecords`) los implementa `FileSessionAdapter`; la app pinta el selector y la confirmación sobre `OverlayBox` y abre el workspace con el camino de `RestoreNamedLayout`.

**Stack:** Swift 6, AppKit, Swift Testing, XCUITest, CryptoKit (solo en el adaptador), Next.js (smalti-web).

**Spec:** `docs/specs/F8.5-proyectos.md`

## Restricciones globales

- `SmaltiCore` sin imports nuevos; la huella es un `String` (hex de SHA-256) que calcula el adaptador.
- Archivo `.smalti/layout.json`, formato 1 de F7 con `"root": "."`; estado `projects.json` (formato 1, 0600) en el directorio de estado.
- Descubrimiento solo al abrir ⌘K o ⌘O; ningún temporizador, observador ni `Task` nuevo.
- Recientes: orden por última apertura, tope 20. Descubrimiento: para en `.git` (incluida), nunca mira el home ni `/`, tope 32 niveles.
- Atajo ⌘O = `project.recent`; `project.save` sin atajo; filas `project.open:<raíz>` en el grupo `projects`, antes de `workspaces`.
- Textos: `ProjectTexts.spanish` / `.english` y `CommandTexts`; vistas en `Localizable.xcstrings`.
- UI tests: `isolatedSmalti(language:)`, `-SmaltiShellCommand "/bin/zsh -f"`, repos en `FileManager.default.temporaryDirectory`, `check-daily-untouched.sh` con `SMALTI_DAILY_PID`, una corrida a la vez.
- `swift test --disable-keychain`; `xcodebuild … -packageAuthorizationProvider netrc`.

## Foco de revisión

1. Archivo cambiado mientras la confirmación está abierta: se abre lo mostrado y se aprueba su huella (T4).
2. Proyecto aprobado cuyo archivo cambió solo en ratios: pide confirmación con «Los comandos son los mismos…» (T3, T4).
3. Monorepo y submódulo: gana el más cercano; un `.git` archivo corta la subida (T2).
4. Reciente cuyo archivo se borró mientras el workspace sigue abierto: sale de la lista, el workspace sigue (T3).
5. Guardar con un panel fuera de la raíz: error con el número del panel, nada escrito (T1, T4).

### Task 4: Casos de uso y workspace del proyecto

**Files:** Create `Application/{OpenProject,ListProjects,SaveProjectLayout}.swift`; Modify `Domain/Workspace/Workspace.swift` (`project: String?`, `markingProject(_:)`), `Domain/Session/SessionSnapshot.swift` (`WorkspaceSnapshot.project`, decodificación sin la clave), `Domain/Session/RestorePlan.swift` (`PlannedWorkspace.project`), `Application/RestoreSession.swift` y `NamedLayoutCommands.swift` (llevan `project`); Test `Tests/SmaltiCoreTests/Projects/{OpenProjectTests,ListProjectsTests,SaveProjectLayoutTests}.swift`, y las de sesión para la clave nueva.

**Interfaces:**
- `OpenProject(files:records:harnesses:home:clock:)`:
  - `prepare(root: String, open: [OpenProjectWorkspace]) throws(ProjectFileError) -> ProjectStep`, donde `OpenProjectWorkspace { id: WorkspaceID; project: String?; window: Int; number: Int }` y `ProjectStep = .jump(WorkspaceID) | .open(PreparedProject) | .confirm(ProjectConfirmation)`. Ya abierto → `.jump` y registra la apertura, sin leer el archivo. Sin comandos o con huella aprobada igual → `.open`. Si no → `.confirm`.
  - `PreparedProject { root; name: LayoutName; snapshot: WorkspaceSnapshot (con project = root); fingerprint; commands: [PlannedCommand] }`; `ProjectConfirmation { prepared; changes: ProjectChanges; approvedAt: Date? }`.
  - `opened(_ prepared: PreparedProject) throws(ProjectFileError)`: registra apertura y aprobación (huella, comandos, paneles, layout, fecha). La app lo llama tras abrir.
  - Los comandos se calculan como `ImportLayout.commands(of:root:)` (extraer a una función compartida `PlannedCommands.of(_:root:home:harnesses:)`).
- `ListProjects(files:records:home:)`: `execute(paneDirectories: [String], focusedDirectory: String?, open: [OpenProjectWorkspace]) -> [ProjectListing]`; poda recientes sin archivo (y reescribe si quitó alguno), descubre desde cada directorio, une por raíz real; `ProjectListing { root; name; lastOpened: Date?; isInFocusedPane: Bool; openIn: OpenProjectWorkspace? }`; orden: el del panel enfocado primero, luego recientes por fecha, luego descubiertos por nombre. El nombre de un descubierto sale del archivo (`layout(at:)`); si no se puede leer, el de la carpeta.
- `SaveProjectLayout(files:records:home:clock:)`: `prepare(_ workspace: Workspace, focusedDirectory: String) throws(ProjectSaveError) -> ProjectSaveStep` (`.write(PendingProjectSave)` o `.confirmReplace(PendingProjectSave)`), con la raíz de la spec («Decisiones», Guardar) y el nombre del archivo existente o de la carpeta («project» si no vale); `write(_ pending) throws(ProjectSaveError) -> LayoutName`: escribe, registra la apertura y aprueba la huella devuelta. `ProjectSaveError = .layout(SharedLayoutError) | .file(ProjectFileError)`.
- [ ] Pruebas rojas: `prepare` nunca toca el motor ni los registros salvo en `.jump`; primera vez con comandos → `.confirm` con `isFirstTime`; misma huella → `.open`; huella distinta → `.confirm` con cambios; sin comandos → `.open`; ya abierto → `.jump` sin leer el archivo; `opened` guarda la aprobación; archivo inválido → error tipado. `ListProjects`: poda y reescribe, une descubierto + reciente, marca panel enfocado y abierto. `SaveProjectLayout`: raíz por cada regla, panel fuera → error sin escribir, archivo existente → `.confirmReplace`, `write` aprueba la huella. `WorkspaceSnapshot` sin `project` decodifica; con él, ida y vuelta; `RestoreSession` y `RestoreNamedLayout` conservan `project`.
- [ ] Implementar; verde. Commit `feat(core): open, list and save projects`.

### Task 5: Adaptador de archivos y estado

**Files:** Create `Packages/FileSessionAdapter/Sources/FileSessionAdapter/{FileProjectFiles,FileProjectRecords}.swift`; Test `Packages/FileSessionAdapter/Tests/FileSessionAdapterTests/{FileProjectFilesTests,ProjectRecordsContractTests}.swift` (el contrato también corre contra `InMemoryProjectRecords`).

**Interfaces:**
- `FileProjectFiles()`: `layout(at:)` lee `<root>/.smalti/layout.json` (tope `SharedLayout.maximumBytes`, decodifica con el decodificador de `SharedLayoutFiles`, valida con `validatedAsProject`), huella = SHA-256 hex de los bytes leídos; `write` crea `.smalti/` y escribe de forma atómica con el mismo codificador que `SharedLayoutFiles` y devuelve la huella de lo escrito; `realPath` con `realpath(3)` (o la ruta tal cual si falla); `hasLayout`/`isRepositoryRoot` con `fileExists`.
- `FileProjectRecords(directory: URL)`: `projects.json` `{ "version": 1, "projects": [...] }`, 0600, directorio 0700; ilegible o formato más nuevo → `all()` vacío sin reescribir hasta el próximo `replace`.
- [ ] Pruebas rojas: huella estable y distinta con un byte cambiado; > 256 KB → error; inválido → `.invalid`; escribir y leer da el mismo layout y la misma huella; `realPath` resuelve un enlace simbólico; contrato de `ProjectRecords` (vacío, reemplazar y leer, orden conservado); permisos 0600.
- [ ] Implementar; `swift test --disable-keychain --package-path Packages/FileSessionAdapter` en verde. Commit `feat(file-session): project files and records`.
