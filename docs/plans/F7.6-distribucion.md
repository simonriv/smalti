# F7.6 · Distribución y actualizaciones — Plan de implementación

> **Para agentes:** ejecución nativa (`.claude/rules/workflow.md`): Claude implementa cada tarea en esta sesión, en bloques, con dos revisiones intermedias y una final acotada. Pasos con casillas (`- [ ]`).

**Objetivo:** distribuir Smalti sin Apple Developer Program (DMG, tap propio, Sparkle con EdDSA y pipeline) con datos que sobreviven a actualizar y a volver atrás.

**Arquitectura:** el dominio decide la compatibilidad de formatos (`FormatCompatibility`) y expone el puerto `AppUpdates`; `SparkleUpdatesAdapter` es el único que importa Sparkle; la app solo conecta comandos, menús y «Acerca de». El pipeline es una envoltura fina sobre `scripts/release/*.sh`, que también corren en local.

**Stack:** Swift 6, AppKit, Sparkle 2.10.1 (SPM `exact`), zsh, `hdiutil`, GitHub Actions (`xcode-27`, `ubuntu-latest`), Homebrew 7.

**Spec:** `docs/specs/F7.6-distribucion.md`

## Restricciones globales

- Versión del primer release público: `0.7.6`, build `706` (`MAJOR×10000 + MINOR×100 + PATCH`), `MACOSX_DEPLOYMENT_TARGET = 27.0`, `ARCHS = arm64`.
- Sparkle: `SUFeedURL = https://smalti.sh/appcast.xml` (solo Release), `SUEnableSystemProfiling = NO`, `SUEnableAutomaticChecks = YES`, `SUAutomaticallyUpdate = NO`, `SUScheduledCheckInterval = 86400`.
- Asset `Smalti.dmg`, tag `vX.Y.Z`, notas en `docs/releases/vX.Y.Z.md`.
- Textos de interfaz en español, exactos de la spec («Buscar actualizaciones…», «Desactivar actualizaciones automáticas», «Activar actualizaciones automáticas», «Abrir la documentación», «Apoyar Smalti…»).
- Enlaces: `https://smalti.sh/es/docs`, `https://smalti.sh/es#apoyar`, issues `https://github.com/simonriv/smalti/issues/new`.
- Ninguna prueba toca `/Applications/Smalti.app`, su estado, `~/.claude` ni `~/.config/smalti`; nunca `brew uninstall --zap` con el cask real; claves y tokens nunca en repo, log ni chat.
- Bundle ID de prueba `dev.simonriv.smalti.updatetest`; servidores en `127.0.0.1` con `trap` que mata el grupo de procesos.

## Foco de revisión

1. Volver atrás de versión con una sesión guardada por la nueva: la vieja no renombra ni sobrescribe `session.json` (T1).
2. `theme.toml` más nuevo y la UI de Apariencia guardando: debe negarse sin perder claves (T2).
3. Abrir la app desde la DMG montada: Sparkle no puede actualizar; README y web lo dicen (T7) y `test-install.sh` copia a «Aplicaciones» como el usuario (T10).
4. Tag que no coincide con `MARKETING_VERSION`, o notas ausentes: el pipeline falla antes de publicar (T8).
5. `<item>` sin `sparkle:edSignature` o con `length` erróneo: el workflow del destino lo rechaza (T8, T9).
